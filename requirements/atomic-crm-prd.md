# Atomic CRM PocketBase 版与墨绿色 UI 重设计 PRD

**版本**：v0.1（草案）  
**目标**：功能保持稳定，小幅增量；全面重做 UI/布局（墨绿色主色，避免蓝/紫及高饱和色），后端迁移至 PocketBase；输出可执行的开发路线与验收标准。

## 1. Purpose & Scope
- 保持现有 CRM 功能（联系人、公司、交易、任务、笔记、活动、导入/导出、认证）。
- UI/UX 大幅重构：主题、布局、组件、响应式、可访问性；使用 SVG 图标，避免蓝紫和高饱和色，主色为墨绿系（低饱和、对比清晰）。
- 后端替换为 PocketBase：认证、存储、数据 CRUD 适配；提供迁移与回滚方案。
- 交付开发路线图与执行检查表。

## 2. Context & Assumptions
- 现有前端：React 19、Vite、React Router v7、React Query、React Hook Form、shadcn-admin-kit、Mutable deps（`src/components/admin`、`src/components/ui`）。
- 现有后端：Supabase（Auth、PostgREST、存储、触发器/视图），即将替换为 PocketBase。
- 数据导入导出：CSV（联系人等），需保持兼容。
- 不支持用户物理删除（禁用代替删除）。

## 3. Goals & Non-Goals
- Goals：
  - 提升可用性与视觉一致性（墨绿主题、SVG 图标、响应式、可访问性）。
  - 确保功能等价迁移到 PocketBase，保留导入/导出与过滤体验。
  - 保持轻量，减少学习成本；可选增量功能以痛点为导向。
- Non-Goals：
  - 不构建复杂计费/订阅/高级自动化工作流。
  - 不实现重度协同或实时并发控制超出 PocketBase 能力的部分。
  - 不引入高饱和或蓝/紫系主题；不使用 emoji。

## 4. Personas & Scenarios
- 销售/顾问：管理联系人、公司、交易；更新看板；记录任务/笔记；导入联系人；快速搜索。
- 主管/管理员：查看管道与活动；导出数据；管理用户（禁用/启用）；配置基础选项。
- 演示访客：使用 demo 数据体验核心流程。

## 5. Functional Baseline（保持不变为主）
- 联系人、公司、交易（Kanban）、任务、笔记、活动、过滤与标签、导入/导出、登录/认证。
- 视图/汇总：保持类似 contacts_summary 语义（在 PocketBase 以规则或派生字段实现）。
- 可选增量（仅当资源允许，默认关闭）：
  - 指令盘/全局搜索（Cmd/Ctrl+K）。
  - 轻量提醒/跟进节奏（任务模板、待办视图）。
  - 发票最小闭环（交易生成发票、状态、PDF 简版）。

## 6. UI/UX 重设计要求
- 主题与色板：
  - 主色：墨绿系（低饱和，避免蓝/紫与高饱和）。
  - 辅色：暖灰/米色系；状态色低饱和红/橙/绿（区分状态但不过饱和）。
  - 对比度满足 WCAG AA。
- 图标：仅用 SVG（线性/双色低饱和），来源可参考 shadcn/Tailwind 图标方案。
- 版式：
  - 导航：桌面侧边栏 + 顶部操作区；移动端抽屉导航。 
  - 列表：桌面表格/卡片，移动端卡片/分组 SimpleList；关键字段优先呈现。 
  - 表单：分组/分段、内联校验、必填标识清晰；重要动作浮动/吸顶。
  - Kanban：列头状态色与墨绿主题协调；卡片信息层次清晰。
- 反馈：一致的空状态、加载骨架、错误提示、进度状态。
- 动效：轻量过渡/层级淡入，避免炫目和大幅位移动画。
- 可访问性：键盘可达、焦点可视、语义标签、ARIA；表单/按钮尺寸适配触控。
- 响应式：断点覆盖手机到桌面；表格在小屏降级为卡片/摘要；导航在 <md 使用抽屉。

## 7. Backend 迁移至 PocketBase
- 认证与 RBAC：
  - 映射角色（admin/sales 等）；支持禁用用户；保持多租户隔离策略（基于 userId 字段规则）。
- 集合设计（对应原表）：contacts、companies、deals、tasks、notes、activities、attachments [可选 invoices、invoice_items]。
- 数据提供器：替换 Supabase 适配层，支持列表/分页/排序/过滤映射；保持现有过滤语义尽可能兼容。
- 文件/附件：使用 PocketBase 存储与访问控制；URL/签名策略明示。
- 视图/派生数据：以 PocketBase 规则/计算字段/预计算集合替代 Supabase 视图与触发器。
- 迁移/ETL：从现有数据导出（或 demo 数据）导入 PocketBase；提供回滚方案与校验步骤。
- 兼容性：CSV 导入/导出字段与现有格式对齐。

## 8. Data Model & Integrations
- ID 策略：使用 PocketBase 默认 ID；记录 created_at/updated_at；软删除以状态字段或禁用代替。
- 验证：服务端规则约束必填、邮箱格式、外键存在性。
- 集成：如需邮件/入站 Webhook，评估 PocketBase 钩子或外部服务替代；附件大小/类型限制需声明。

## 9. 性能、可靠性、安全、隐私
- 目标：
  - 列表首屏 < 2.5s（冷启动），交互中请求 < 1s（命中缓存更快）。
  - React Query 缓存与乐观更新用于常规 CRUD。
- 安全：
  - PocketBase 规则保证记录级隔离；最小权限访问；附件访问控制。
  - 审计/日志：关键操作可选记录；避免泄露敏感字段。
- 隐私与合规：
  - 允许 telemetry 关闭（disableTelemetry 兼容）；日志/监控需脱敏。

## 10. Rollout & Migration
- 环境：demo（FakeRest 或 PocketBase demo）、staging（PocketBase）、prod。
- 步骤：
  - 搭建 PocketBase 与集合规则 → 数据提供器替换 → 前端连通性验证 → UI 重构逐步开关。
  - 数据迁移演练：导出/导入、行数与哈希校验；必要时并行运行旧后端只读模式。
- 回滚：保留旧数据快照/导出，PocketBase 侧支持恢复。

## 11. Risks & Open Questions
- PocketBase 不支持 SQL 视图/触发器的等价特性需要规则/计算字段替代，复杂度待评估。
- 附件大小/类型限制与带宽成本。
- 移动端表格降级的可用性与性能（长列表）。
- 如启用发票模块，PDF 字体体积与加载时机需权衡。

## 12. Acceptance Criteria & QA
- 功能等价：联系人/公司/交易/任务/笔记/活动/过滤/导入导出在 PocketBase 正常运行。
- UI：墨绿主题、无蓝/紫/高饱和色；SVG 图标；响应式与可访问性检查通过（键盘、焦点、对比度）。
- 性能：列表/详情/更新满足目标；空状态与错误提示一致。
- 数据：PocketBase 集合规则生效；未授权访问受阻；附件权限符合预期。
- 测试：类型检查、lint、核心流冒烟；若有发票/指令盘等增量则覆盖其冒烟用例。

## 13. Milestones & Roadmap
1) PocketBase 基线：集合/规则/存储、数据提供器与认证适配、CSV 兼容验证。  
2) UI 框架落地：主题令牌（墨绿系）、导航/布局、列表卡片降级、表单与反馈模式。  
3) 国际化框架（若启用）：中英文案、切换入口、格式本地化。  
4) 可选增量：指令盘/搜索、轻量提醒/节奏、发票 MVP。  
5) QA 与打磨：可用性走查、移动端检查、无障碍与性能。  
6) 上线与文档：运行/部署说明、迁移/回滚指引。

- [ ] 集合与规则定义（contacts/companies/deals/tasks/notes/activities/attachments [+ invoices/items 可选]）
- [ ] RBAC/记录级访问策略与禁用流程
- [ ] 数据提供器与认证适配（过滤/分页/排序映射，文件上传）
- [ ] CSV 导入/导出字段对齐与验证
- [ ] UI 主题与组件重构：导航、表格/卡片、表单、空状态、反馈、动效
- [ ] 响应式与可访问性检查（对比度、键盘、焦点、触控尺寸）
- [ ] SVG 图标集与状态色规范（无蓝紫，高饱和禁用，墨绿主色）
- [ ] 性能与缓存策略（React Query、乐观更新）
- [ ] 可选增量：指令盘/搜索、提醒/节奏、发票 MVP（含 PDF 字体方案）
- [ ] QA：类型检查、lint、核心流冒烟、移动端视图检查
- [ ] 文档：运行/部署、迁移/回滚、配置项与限制

## 15. Out-of-Scope
- 复杂计费/订阅与高级自动化工作流。
- 高饱和或蓝紫主题；emoji 视觉元素。
- 重度实时协作（超出 PocketBase 能力范围的并发控制）。
